# Core stays small. The rest is revealed.

Keith 2026-09-25. Optimize COSMOS by subtraction. The core is always on.
Extra function stays dark until the user wants it, or the work order names it.
A feature that is loaded and not used is a context tax. That tax is worse
on open and local models.

This is not a second settings app. Reveal means: that layer enters this
attempt's pack and tool pool, then leaves when the attempt ends.

## COSMOS (control plane)

Always on: one pen, the lease, propose-only, no second writer.

Dark until named: WOMBAT, Judge, Auditor, Scribe, extra seats, XTalk,
collector/runner tasks, a live-ledger re-sign.

## How a reveal happens

1. User says so, or the WO names the layer.
2. That layer's bytes enter this attempt only.
3. The tool list offered to the model is the core plus that layer.
4. Attempt ends. The extra layer is dark again.

`require_duds` still only checks the outfit that was actually bound.
A written file is not a pass. Applied means the door bound what it claimed
and the reply obeyed.

## cDeck

cDeck is the human reveal surface. It is a client of Core (`cdeck.exe`, loopback). It is not the pen, and it is not model context.

Two reveals, do not mix them:

| Reveal | Who sees it | What "on" means |
|---|---|---|
| CODE pack | The model, this attempt | A layer's bytes are in the prompt and the tool list |
| cDeck pane | Keith | That `deck_*.js` module is loaded because he opened the tab |

Opening WOMB, XTalk, fleet, or studio paints the pane. It does not summon the seat and it does not stuff that pane into a coder prompt. Arming a seat is a named command. Core still refuses if the pen is not his.

Dark pane ≠ deleted pane. The module stays on disk. The first paint does not load every `deck_*.js`. Loading them all "so they are there" is the fat pack, in the UI.

Spawn form on the deck may edit Role×Model defaults. Enforcement stays in Core. The form can show seven fields. The model receives only the layers that are on for this attempt.

Separate window from OpenWork. Do not fold the CODE loop into cDeck, or cDeck into the system prompt.

### Three modes (chrome only)

Keith 2026-09-25: Ultralight / Cruiser / Flightdeck. This is how much deck is offered. It is not a profile, not a skin, and not `data-orch-mode`. Profile picks the product tree. Skin paints it. Mode picks how many panes are in the rail.

The mode is UI state. It does not write the lease, clear pause, or summon a seat. Opening a pane still only paints.

| Mode | Rail offers | Still dark |
|---|---|---|
| Ultralight | Header, pen/lease, pause, home | Every other `deck_*.js` |
| Cruiser | Ultralight plus the daily run: orders, jobs, runs, review, Gitur status, backup | Womb summon, XTalk, fleet, studio, forge, voice, nodemap, jukebox |
| Flightdeck | The full rail is visible | Scripts still load on tab open, not at first paint |

Flightdeck is not "load every file at boot." That is the fat pack. A pane file stays on disk in every mode. Ultralight does not delete it. It only refuses to offer it.

## Not

Boot every tool "so it is there." A maximalist default tuned for a demo.
Progressive disclosure as a slogan with the fat pack still in the system turn.
Writing the loop before this split is the spec.
