# Gateway

Hermes runs one messaging gateway process. Adapters normalize inbound events, and the runner accepts a message only for a platform that process has registered. The same message id is the first receipt again, not a second apply. A bad signature or a bad fence refuses, and a stale fence refuses. Shutdown drains the process: new ingest is refused, and a reply can still be recorded for a platform already registered. Stock Hermes also starts watcher loops for sessions, delivery recovery, and health. This proposal does not.

The live seam is new. COSMOS has no messaging gateway runner. `cosmos_approval.py` and the fenced-commit gateway are different seams, and this package does not import them.

This proposal adds `Gateway.register_platform`, `ingest`, `deliver`, `shutdown`, `status`, `snapshot`, `sign`, and `rebuild`. `ingest` returns an `IngestResult`. The receipt on an exact repeat is the same object, `replay` is the replay mark, and the ledger does not grow. The same id with a different signed body is `MISMATCH` and does not apply. The id namespace is the whole gateway. Ids and signatures are compared with `const_eq`. `sign` is HMAC-SHA256 over a length-prefixed canon, keyed by the platform credential id. That id is not key material. The fence is a caller timestamp. A new message must sit within 300 seconds of the caller `now` and must not move backward on that platform. An exact retry still returns the stored receipt after that window. `deliver` returns a descriptor for a registered target and does not send. An unknown platform is `UNKNOWN_PLATFORM`. `shutdown` then makes `ingest` and `register_platform` raise `DRAINING`. `status` is a snapshot of counts. `snapshot` plus `rebuild` replays the hash chain. Constructing a gateway starts no thread and no watcher process.

Authority is the in-memory ledger on that gateway value. The caller supplies the platform name, the credential id, the message id, the body, the signature, the fence, and the clock. The package holds no raw secret, accepts no path, opens no socket, and writes no file.

`MESSAGE_CAP` is 8000 characters. `QUEUE_CAP` is 128 accepts and, separately, 128 delivery descriptors. `PLATFORM_CAP` is 32 names. `FENCE_WINDOW` is 300 seconds and is not a caller argument. A caller who asks for a higher message, queue, or platform cap keeps the policy cap, and the policy records the asked value. A lower positive cap is applied. Names are lowercase tokens. Secret-shaped text is refused and is not stored. There is no retry loop. There is no `off` mode and no `yolo` mode.

## Ship

- operations: `FENCE_WINDOW`, `MESSAGE_CAP`, `PLATFORM_CAP`, `QUEUE_CAP`, `SCHEMA`, `Delivery`, `Gateway`, `IngestResult`, `Platform`, `Policy`, `Receipt`, `Shutdown`, `Snapshot`, `Status`, `rebuild`, `sign`. Methods: `register_platform`, `ingest`, `deliver`, `shutdown`, `status`, `snapshot`.
- refusal codes: `UNKNOWN_PLATFORM`, `DRAINING`, `SECRET`, `BAD_NAME`, `BAD_ID`, `BAD_SIGNATURE`, `BAD_FENCE`, `STALE`, `EMPTY_MESSAGE`, `NOT_TEXT`, `NULL_BYTE`, `OVERSIZE`, `QUEUE_CAP`, `PLATFORM_CAP`, `DELIVERY_CAP`, `NOT_INT`, `OUT_OF_RANGE`, `MISSING`, `MISMATCH`, `CHAIN`, `DUPLICATE`, `BAD_RECORD`, `BAD_POLICY`.
- what this module still refuses to execute: sockets, HTTP servers, watcher threads, session loops, delivery recovery, health probes, platform sends, a vault HMAC that would need raw key material, a second apply of a message id, and any retry loop. A credential id is not a live connection. The hash chain is not a substitute for a vault signature.
- hot-path shape: one validation pass, one HMAC, then a dict lookup of the message id. An exact replay returns the stored receipt and does not append. A new message that does not fit the queue cap is refused without dropping earlier receipts. Name and id membership are dicts. The fence window is a constant compare, not a scan.

CCr would land this later as one in-process runner beside the platform adapters. The idempotency ledger stays the authority for replay, and drain stays a state bit a service clock can observe. Socket adapters stay in the platform layer and stay disabled until a credential id exists. No watcher thread moves with this package.
