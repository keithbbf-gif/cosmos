# clarify_todo

Hermes asks the user with the `clarify` tool and keeps a session checklist with `todo`. Clarify shows one question, or a short batch of independent questions, and waits for the human. The documented batch is 1 to 5 questions. Messaging platforms use a timeout. The CLI waits. The checklist covers multi-step work in the current session and is shown again after context compression. Items may be plan lines. The checklist is a plan. It is separate from kanban and from the shell.

The live seam is inert todos. No COSMOS module owns session questions or an executing checklist.

`clarify(questions, requested_cap)` returns a frozen `Clarify` copy. An empty list or empty tuple raises `NOTHING_TO_ASK`. The question cap is 5. A request above 5 is recorded as 5. A lower positive request is recorded as asked. Six or more questions raise `QUESTION_CAP` and store nothing. Leading and trailing whitespace is removed. The caller’s list is not the stored batch. `open_list(requested_cap)` records the item cap. A request above 32 is recorded as 32. A lower positive request is recorded as asked. Later adds leave that cap in place and still refuse a malformed requested cap. `add_todo(text, todo_list)` appends one open item. The id is the next integer starting at 1. The first call may omit the list. `done(id, todo_list)` marks that id done and leaves every other field of that row, and every other row, unchanged. A second call on the same id returns the same list. `kind` is `plan` or `shell`. Omitted kind is taken from the text. A supplied kind that disagrees with the text raises `BAD_KIND`. A line that asks to run a shell is stored as `shell` and stays inert. `snapshot` emits the rows. `rebuild` restores the same public list. `run` raises `NOT_A_TOOL` for a bare call, a whole list, and a known id, including a shell line.

Authority for the answer and for the work sits with the human. The checklist is an in-memory frozen record for the session. Snapshot and rebuild copy that record. They are not a ledger append, not a projection file, and not an attempt workspace. Done records status only. There is no retry class. This module accepts no path and no credential.

Refusal codes are `NOTHING_TO_ASK`, `BAD_QUESTIONS`, `QUESTION_CAP`, `TODO_CAP`, `UNKNOWN_TODO`, `NOT_A_TOOL`, `SECRET`, `EMPTY`, `BAD_LIST`, `NOT_TEXT`, `NULL_BYTE`, `OVERSIZE`, `NOT_INT`, `BAD_LIMIT`, `OUT_OF_RANGE`, `STALE`, `DUPLICATE`, and `BAD_KIND`. Every question and item passes `bound_text` at 500 characters. `secret_shape` text is refused, so record `repr` stays free of key material. The question cap is 5. The item cap is 32. One more item raises `TODO_CAP`. An id outside `1..32` on a record raises `OUT_OF_RANGE`. An id that is absent from the list raises `UNKNOWN_TODO`. A repeated id raises `DUPLICATE`. A schema that is not this module’s schema raises `STALE`.

CCr would land this later as a session record beside the harness loop. The clarify result is handed to the human turn as bounded question text. This copy does not render choices, wait, or deliver a card. The checklist stays in memory for that session. `run` stays a refusal, so a todo stays a plan line rather than a tool call, a shell, a cron row, or a kanban transition. The landing writes no file and spawns no worker.

## Ship

- operations: `KINDS`, `QUESTION_CAP`, `SCHEMA`, `TEXT_LIMIT`, `TODO_CAP`, `Clarify`, `Record`, `Snapshot`, `Todo`, `TodoList`, `add_todo`, `clarify`, `done`, `open_list`, `rebuild`, `run`, `snapshot`
- refusal codes: `NOTHING_TO_ASK`, `BAD_QUESTIONS`, `QUESTION_CAP`, `TODO_CAP`, `UNKNOWN_TODO`, `NOT_A_TOOL`, `SECRET`, `EMPTY`, `BAD_LIST`, `NOT_TEXT`, `NULL_BYTE`, `OVERSIZE`, `NOT_INT`, `BAD_LIMIT`, `OUT_OF_RANGE`, `STALE`, `DUPLICATE`, `BAD_KIND`
- what this module still refuses to execute: a question batch, a plan line, and a shell-classified line. `run` is `NOT_A_TOOL` and does not read the line as argv. Marking done replaces the record only. No shell, no card delivery, no wait, no file, and no worker.
- hot-path shape: one pass over the question tuple or the checklist. Each new line is bounded and secret-scanned once. Shell class is one compiled search. `run` builds one id set and does not scan text. A higher cap is ignored and the policy cap is recorded. A batch or list past the count cap refuses. Later lines are not dropped to make room. `done` copies the row without a second scan.
