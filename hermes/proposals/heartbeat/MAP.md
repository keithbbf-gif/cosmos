# heartbeat

Hermes attaches one recurring instruction to the current session with `/heartbeat every <interval> <prompt>`. Documented intervals use `90s`, `10m`, `2h`, and `1d`. The slash command's minimum is 60 seconds. `/heartbeat` and `/heartbeat status` show the instruction, the interval, and the time until the next fire. `/heartbeat pause` stops firing without clearing the instruction. `/heartbeat resume` re-anchors the timer so a stale tick does not fire at once. `/heartbeat clear` removes it. `/hb` is an alias. The tick is injected only while the session is idle, as one ordinary user message, never mid-run. Several missed intervals coalesce into that one fire, and the timer re-anchors on the fire. A queued user message wins over a due tick. The surface that set the heartbeat owns the fire. Gateway startup restores an active heartbeat from SessionDB under `heartbeat:<session_id>` and does not resurrect a paused, cleared, reset, or switched conversation. A tick that enters the agent runner stays counted even when the model call fails or is interrupted. That count is liveness, not proof of a successful reply or a delivered message. A bare `NO_REPLY` or `[SILENT]` marker sends nothing. The injected wording tells the agent to stay quiet when nothing meaningful changed.

The live seam is the liveness record. `cosmos/cosmos_clock.py` already stores a worker tick and an age through `write_heartbeat`, `read_heartbeat`, and `heartbeat_age_s`. Those helpers read the OS clock and write a file. This proposal does not replace that writer.

`Heartbeat(interval_s)` records the requested interval and keeps an effective interval. A request below 15 is stored on `requested`, and the effective interval stays 15. A request from 15 through 2147483647 is both the requested value and the effective interval. A larger request is refused and does not raise that ceiling. `beat(now, task_ok)` records a frozen `Beat` whose `alive` field is true even when `task_ok` is false, and it moves the watermark to the caller `now`. A later `now` is fresh. The same `now` again is `REPLAY` and leaves the record unchanged. A `now` behind the watermark is `STALE` and does not move it. Beats at 100 and 130 are fresh. A beat at 90 after 130 is stale. `miss(now)` is true only when a beat exists and `now - last` is greater than the effective interval. Equal to the interval is not a miss. A gap of many intervals is still one due beat, and the next fresh `beat` clears it. `now` is an int the caller passes. This module starts no thread, calls no sleep, and returns no scheduler. `rebuild` replays the emitted beats into the same public snapshot.

The caller owns the clock value. The attempt owns task success. The ledger, the projection, and the attempt workspace stay outside this module. A later clock service is what would persist a beat.

## Ship

- operations: `Beat`, `Heartbeat`, `Interval`, `MIN_INTERVAL_S`, `POLICY_CAP`, `SCHEMA`, `Snapshot`, `rebuild`. `Heartbeat` also exposes `beat`, `miss`, `snapshot`, `interval`, `requested_s`, `interval_s`, `alive`, `task_ok`, and `last_at`.
- refusal codes: `BAD_INTERVAL`, `BAD_RECORD`, `BAD_SCHEMA`, `MISMATCH`, `NO_BEAT`, `NOT_ALIVE`, `NOT_BOOL`, `NOT_INT`, `NOT_TEXT`, `NULL_BYTE`, `OUT_OF_RANGE`, `OVERSIZE`, `REPLAY`, `STALE`
- what this module still refuses to execute: sleep, a thread, a scheduler, an OS clock read, a heartbeat file write, prompt injection, gateway delivery, silence-marker handling, pause and resume, and any retry of a beat. A paused, cleared, reset, or switched conversation is not resurrected here. The session owner keeps the prompt and the `heartbeat:<session_id>` key.
- hot-path shape: one watermark compare on `beat`, one subtraction on `miss`. `rebuild` is one forward pass and refuses on the first mismatched, stale, or replayed beat. No history scan on the live beat.

CCr lands this beside `cosmos_clock.write_heartbeat`. The service asks `miss` with its caller clock and, when a turn is admitted, calls `beat` even if the task fails. The file write and the OS clock stay in `cosmos_clock.py`. The session owner keeps the prompt, pause, and the `heartbeat:<session_id>` key. The floor stays 15 seconds. Nothing here sleeps or starts a watcher.
