# terminal_backends

Hermes runs terminal commands, file tools, and `execute_code` through one of seven backends. `local` uses the host account and has no isolation. `docker` keeps one long-lived container and execs into it. `ssh` runs on a remote host and keeps a persistent shell. `singularity` runs an Apptainer container with namespace containment. `modal` and `daytona` are cloud sandboxes. `vercel` is the Vercel Sandbox microVM. Hermes configures that backend as `vercel_sandbox`. This catalog's name for it is `vercel`. The default backend is `local`. The default per-command timeout is 180 seconds. Daytona disk requests above 10 GiB (10240 MB) are capped. Vercel accepts only the shared 51200 MB disk figure and rejects a custom size. SSH needs a hostname, a user, and a key. A shell string is not an argument vector. Docker may forward env names, not values. Background sessions, container reuse, and remote state sync stay outside this package. The package records the choice and does not start a process, a pty, a container, or a socket.

## Live seam

`cosmos/cosmos_sandbox.py` owns attempt spawn. The composed host backend is a Windows job object (kill-on-close). Daytona and E2B are remote transports that refuse with `UNCONFIGURED` until a credential file exists. Modal is named there and is not composed. An unknown sandbox name raises `UNKNOWN_BACKEND`. This proposal does not import that module. The seven Hermes terminal names are a policy catalog in front of that seam. `job_object` is not one of the seven, and a Hermes `vercel_sandbox` string is not an alias. Naming a backend returns a descriptor. `execute` on an unsandboxed backend refuses until wipe-proof data is supplied. A path jail is not that proof.

## Operations

`spec(name)` returns a frozen `BackendSpec`. `policy_only` is true. `local` is classified `UNSANDBOXED` with isolation `none`. The other six are classified `UNPROVEN` until a proof is presented at `execute`. The name is one of `local`, `docker`, `ssh`, `singularity`, `modal`, `daytona`, and `vercel`. Any other name, including `off`, `yolo`, and `vercel_sandbox`, raises `UNKNOWN_BACKEND`. `remote` is true for `ssh`, `modal`, `daytona`, and `vercel`. Those four require a credential id. A timeout above 180 seconds and at most 1000000000 is recorded and applied as 180. A lower positive timeout stands. Docker and Modal disk requests above 51200 MB are applied as 51200. Daytona disk requests above 10240 MB are applied as 10240. Vercel, local, SSH, and Singularity reject a caller-supplied disk.

`plan` copies a list of arguments into a frozen `TerminalPlan`. A `str` command raises `SHELL_STRING`. Secret-shaped text raises `SECRET_SHAPE` before that shell check. The list is not executed. The list holds at most 32 arguments, and each argument holds at most 4096 characters. A longer list is refused. Arguments are not dropped. Docker `env_names` are identifiers. A name that does not fit the remaining 64-character budget is skipped. Later names that fit are kept. An over-long input list is refused. Other backends refuse env names. An SSH host must match `^[A-Za-z0-9.-]{1,253}$` or the call raises `BAD_HOST`. Any other backend refuses a host. An SSH user is a short token. A credential id is compared with `const_eq` when the caller passes an expected id. A local work directory and a Singularity image path go through `PathJail`. Other backends refuse a host path. Image references stay literal names, not shell text. `pty=True` raises `PTY`. `background=True` raises `BACKGROUND`.

`issue_proof` seals caller-supplied wipe-proof data: proof schema, backend, credential id, proof id, and stamp. The digest is computed once. `local` cannot be proven. A bool is not a proof. `execute` runs the same checks as `plan` and then raises `UNSANDBOXED` for `local`, for a missing proof, for a bool, and for a lookalike. Docker without a proof raises `UNSANDBOXED`. A proof whose stamp differs from the caller timestamp is `STALE`. A matching proof returns a frozen `TerminalOrder` classified `SANDBOXED`. The order is a descriptor. It does not spawn.

`snapshot` seals plans into a `Catalog` and hashes the chain once. Duplicate non-empty task ids refuse. `rebuild` from those plans returns the same catalog.

## Authority

The attempt sandbox and the human approval gate own execution. This package does not. `policy_only` is a label, not a sandbox. `WipeProof` is data a caller supplies from a measured sandbox snapshot, not a boolean this package can flip. Passing a proof does not start a container or a pty. Credential fields hold ids, never raw key material. A jailed directory without wipe-proof data stays unsandboxed, and `local` stays unsandboxed even when proof data is passed. No retry runs, because nothing is attempted.

A path that is present also raises the `PathJail` code for that shape, including `RELATIVE_PATH`, `OUTSIDE_GRANT`, `DOTDOT`, `ENCODED_DOTDOT`, `UNC`, `FILE_URL`, `DRIVE_ROOT`, `DRIVE_RELATIVE`, `ALT_STREAM`, and `TRAILING_DOT`.

## Landing

CCr would call `spec` in the terminal gate and keep every one of these seven records `policy_only`. A command string stays `SHELL_STRING` here and in the platform adapter. `issue_proof` would be filled only from a measured sandbox snapshot outside this package. An approved argv list plus that proof is the only shape that may later reach `cosmos_sandbox`, and only for a composed backend. `execute` here still returns a descriptor and does not become a client. SSH continues to take a hostname. No container client, SSH client, pty, scheduler, or socket is added here.
