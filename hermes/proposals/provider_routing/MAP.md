# provider_routing

Hermes, on OpenRouter, sends a `provider` object that can sort by price, throughput, or latency, restrict with `only`, exclude with `ignore`, pin an `order`, require full parameter support, and set data collection to allow or deny. Per-model blocks override those keys for the model the agent is on. Nous Portal ignores the object. Direct provider connections do not use it. When the section is absent, the aggregator ranks by its own default. Unlisted names in `order` are fallbacks on the aggregator. Model ids match with or without an `openrouter/` prefix, and `.` matches `-`.

The live seam is `cosmos/cosmos_openrouter_rail.py` (rails). That rail already pins a named model and a narrow `provider.only` list, with fallbacks disabled. `cosmos/cosmos_route_variant.py` only appends a suffix priority (`floor`, `nitro`, `exacto`). Neither module refuses an unknown provider instead of another vendor, and neither routes one named model against an explicit model allowlist. This proposal is that decision. It performs no network and does not read a rail key.

`route` returns a frozen `Decision` for one named model. The model must sit on the explicit allowlist. The chosen provider must sit on `only`, must be in the caller catalog `known`, and must have an `Offer` for that model. `ignore` removes a provider even when `only` names it. A non-empty `order` is a priority among those providers and does not add anyone outside that list. Sort is `price`, `throughput`, or `latency`. Ties break by provider name. A per-model `Pin` overrides the keys it sets; a field left as `None` keeps the policy value. `portal` and `direct` refuse. An empty allowlist, an empty catalog, and an empty `only` refuse. A provider the catalog does not name refuses. A model outside the allowlist refuses. No other vendor is substituted. A cost above the remaining budget is skipped; a later offer that fits is still eligible. Caps above `POLICY_CAP` and `BUDGET_CAP` are ignored and the policy values are recorded. `snapshot` emits one `RouteRecord`. `rebuild` from that record reproduces the decision. The module schema is `cosmos-hermes-provider_routing/1`.

Authority is human. The caller supplies the catalog, the measurements, the allowlists, the credential id, and the timestamp. The function returns a descriptor. It does not spend, write a ledger, or call a provider. Spend stays on `cosmos/cosmos_spend.py`.

Refusal codes: `BAD_SURFACE`, `NOT_OPENROUTER`, `MISSING_CRED`, `BAD_CRED`, `SECRET`, `BAD_MODEL`, `BAD_PROVIDER`, `BAD_LIST`, `BAD_OFFER`, `BAD_PIN`, `BAD_POLICY`, `EMPTY_ALLOW`, `EMPTY_ONLY`, `EMPTY_KNOWN`, `DUPLICATE`, `BAD_SORT`, `BAD_COLLECTION`, `BAD_FLAG`, `UNKNOWN_PROVIDER`, `NOT_ALLOWED`, `NO_PROVIDER`, `DENIED`, `NO_FALLBACK`, `PARAMS`, `BUDGET`, `BAD_CAP`, `BAD_RECORD`, `BROKEN`, `STALE`, plus kernel codes `NOT_TEXT`, `NULL_BYTE`, `OVERSIZE`, `NOT_INT`, and `OUT_OF_RANGE`.

CCr would later call `route` with the OpenRouter rail's named model, the human allowlist, and offers already measured on the projection, then pass `Decision.provider` as the single `provider.only` entry. An unknown provider still refuses. A model outside the allowlist still refuses. No second HTTP client is added.

## Ship

- operations: `ASK_CAP`, `BUDGET_CAP`, `CRED_CAP`, `Decision`, `FIELD_CAP`, `MODEL_CAP`, `NAME_CAP`, `Offer`, `POLICY_CAP`, `Pin`, `Policy`, `RouteRecord`, `SCHEMA`, `rebuild`, `route`, `snapshot`
- refusal codes: `BAD_SURFACE`, `NOT_OPENROUTER`, `MISSING_CRED`, `BAD_CRED`, `SECRET`, `BAD_MODEL`, `BAD_PROVIDER`, `BAD_LIST`, `BAD_OFFER`, `BAD_PIN`, `BAD_POLICY`, `EMPTY_ALLOW`, `EMPTY_ONLY`, `EMPTY_KNOWN`, `DUPLICATE`, `BAD_SORT`, `BAD_COLLECTION`, `BAD_FLAG`, `UNKNOWN_PROVIDER`, `NOT_ALLOWED`, `NO_PROVIDER`, `DENIED`, `NO_FALLBACK`, `PARAMS`, `BUDGET`, `BAD_CAP`, `BAD_RECORD`, `BROKEN`, `STALE`, `NOT_TEXT`, `NULL_BYTE`, `OVERSIZE`, `NOT_INT`, `OUT_OF_RANGE`
- what this module still refuses to execute: it does not call OpenRouter, does not open a socket, does not write a ledger, and does not substitute another vendor when the named model is outside the allowlist, the provider is unknown, the provider is off `only`, or `order` does not name a serving provider. It does not raise `POLICY_CAP` or `BUDGET_CAP`. It does not treat Portal or a direct connection as an aggregator route.
- hot-path shape: one pass groups offers by model key with set membership for the catalog and the allowlists, then ranks that model's eligible slice and skips costs that do not fit the budget without dropping a later offer that fits
