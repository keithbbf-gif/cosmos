# Hooks

Hermes runs gateway handlers, plugin callbacks, shell scripts, and outbound webhooks at lifecycle points. Gateway handlers subscribe to events such as `gateway:startup`, `session:*`, `agent:*`, and `command:*`. A plugin `pre_tool_call` callback can block the call, escalate it for approval, or modify arguments. `post_tool_call` observes the result. A stop directive can hold the turn open. Hermes records a callback error and continues with the next callback. A block wins over an earlier approve.

The live seam is `cosmos_harness.hooks`. That module already runs `pre_tool`, `post_tool`, and `stop` inside a fixed eight-hook order, and a refused decision latches the attempt. It keeps no caller registry and has no gateway point.

This proposal adds `Registry.register` and `Registry.fire` for `pre_tool`, `post_tool`, `stop`, and `gateway`. The host injects the callables. They run inline, in registration order within that point. A `Refuse` returned or raised latches: later hooks do not run, and the action refuses with that code. Any other exception refuses as `HOOK_FAIL`. Tool names on a result, including a `tool:` marker in a note, must be a subset of the action allowlist. Any other name refuses as `GUARD_ESCAPE`. The policy cap is 16. A higher requested cap is stored on `asked_cap` and the effective cap stays 16. A lower request is a tighter ceiling. `CONFIRM` is the only retried class, and that same hook runs at most once more. Plan mode on a tool point admits only the harness plan hands `read`, `glob`, `grep`, and `oracle`. There is no `off` and no `yolo`.

Each admitted hook appends one `Line` on the verdict and on `transcript`. The line carries the point, so a pre pass and a post pass around one tool are different lines. Lines commit only when the fire admits. `get` on a name that was not registered raises `UNKNOWN_HOOK`. `rebuild` checks an emitted transcript and returns the same lines. An exact duplicate line raises `DUPLICATE`. A stamp that moves backwards raises `STALE`. `load_from_path` raises `IMPORT` and does not open the path. A string is not a hook body.

Authority sits in the attempt workspace. The harness allowlist is the only tool grant. The verdict repeats that allowlist. A hook can observe or refuse. It cannot add a tool, open a socket, or write the ledger. A gateway verdict is a descriptor for a later delivery service. A human supplies the callable. A credential is an id. Raw key material refuses as `SECRET`.

Refusal codes: `BAD_CAP`, `BAD_NAME`, `BAD_CRED`, `BAD_EVENTS`, `BAD_RESULT`, `BAD_TOOL`, `BAD_ALLOW`, `BAD_CONFIRM`, `DUPLICATE`, `UNKNOWN_POINT`, `UNKNOWN_HOOK`, `UNKNOWN_EVENT`, `UNKNOWN_MODE`, `UNCLASSIFIED`, `EMPTY_ALLOW`, `EMPTY_EVENTS`, `MISSING_TOOL`, `MISSING_CRED`, `CRED_MISMATCH`, `NOT_ALLOWED`, `NOT_CALLABLE`, `PLAN_MODE`, `SECRET`, `HOOK_CAP`, `HOOK_FAIL`, `GUARD_ESCAPE`, `CONFIRM`, `REENTER`, `NO_GRANT`, `IMPORT`, `STALE`, plus bound and jail codes `NOT_TEXT`, `NULL_BYTE`, `OVERSIZE`, `NOT_INT`, `OUT_OF_RANGE`, `OUTSIDE_GRANT`, `RELATIVE_PATH`, `DOTDOT`, and the other `PathJail` codes that pass through (`FILE_URL`, `ENCODED_DOTDOT`, `UNC`, `DRIVE_ROOT`, `DRIVE_RELATIVE`, `ALT_STREAM`, `TRAILING_DOT`, `BAD_PATH`, `RELATIVE_GRANT`).

CCr lands the registry on `cosmos_harness.hooks`. The loop calls `fire` at `pre_tool`, `post_tool`, and `stop` before the built-in decision, and gateway ingest calls `fire` for gateway events. A latch becomes the harness halt. The built-in eight-hook order stays the control flow. Directory discovery, shell scripts, and outbound HTTP stay out of the landing.

## Ship

- Operations: `ALLOW_CAP`, `ASK_CAP`, `COMMAND_WILDCARD`, `GATEWAY_EVENTS`, `NOTE_CAP`, `PLAN_TOOLS`, `POINTS`, `POLICY_CAP`, `SCHEMA`, `TEXT_CAP`, `TRANSCRIPT_CAP`, `Action`, `Hook`, `HookFn`, `Line`, `Outcome`, `Registry`, `Verdict`, `load_from_path`, `rebuild`. Registry methods are `register`, `fire`, `get`, `transcript`, and `load_from_path`.
- Refusal codes: `BAD_CAP`, `BAD_NAME`, `BAD_CRED`, `BAD_EVENTS`, `BAD_RESULT`, `BAD_TOOL`, `BAD_ALLOW`, `BAD_CONFIRM`, `DUPLICATE`, `UNKNOWN_POINT`, `UNKNOWN_HOOK`, `UNKNOWN_EVENT`, `UNKNOWN_MODE`, `UNCLASSIFIED`, `EMPTY_ALLOW`, `EMPTY_EVENTS`, `MISSING_TOOL`, `MISSING_CRED`, `CRED_MISMATCH`, `NOT_ALLOWED`, `NOT_CALLABLE`, `PLAN_MODE`, `SECRET`, `HOOK_CAP`, `HOOK_FAIL`, `GUARD_ESCAPE`, `CONFIRM`, `REENTER`, `NO_GRANT`, `IMPORT`, `STALE`, `NOT_TEXT`, `NULL_BYTE`, `OVERSIZE`, `NOT_INT`, `OUT_OF_RANGE`, `OUTSIDE_GRANT`, `RELATIVE_PATH`, `DOTDOT`, `FILE_URL`, `ENCODED_DOTDOT`, `UNC`, `DRIVE_ROOT`, `DRIVE_RELATIVE`, `ALT_STREAM`, `TRAILING_DOT`, `BAD_PATH`, `RELATIVE_GRANT`.
- This module still refuses to execute hook bodies, shell scripts, plugin imports, and outbound HTTP. `load_from_path` does not open a path. A callable the host did not pass never runs. A hook cannot widen the allowlist. There is no scheduler and no file write.
- Hot path: one pass over the hooks registered at that point, in registration order. Allowlist, event, and name checks are set membership. Credential ids use `const_eq`. A refusal latches and later hooks do not run. Lines append only after the fire admits, so a latch does not leave a partial transcript that a second attempt would double.
