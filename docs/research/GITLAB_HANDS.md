`docs/COSMOS_PIPELINE.md` (2026-08-23) left this open: *"`VENDOR_FEATURES_2026-08-20` could not confirm the program exists… Two questions, both behind the connected account: WHICH PRODUCT, and DOES IT EXPIRE."*

**Verdict from official docs this session: there is no documented "$200 GitLab compute" product.** Do not write a spend plan against a $200 GitLab balance. That number is Cursor Ultra ($200/mo, SuperGrok Heavy → $0 marginal — DHx / `ROUTING.md`), not GitLab.

**Answers to the two questions:**

1. **WHICH PRODUCT?** None called "$200." The live free compute product on GitLab.com Free is **400 hosted-runner minutes / month**. Extra minutes are a **$10/1k pack**, not a $200 grant. GitLab Credits are a **Duo/agent** currency, not CI minutes.
2. **DOES IT EXPIRE?** The 400 Free minutes expire at month-end (reset, no rollover). Purchased extra minutes: 12-month documented life. Credits: monthly reset, no rollover. Education/OSS/Startups: program term.

**Compute that does not burn the 400:** **project runners and group runners are not subject to the instance-runner compute quota** and keep processing after the quota is exhausted ([compute usage for instance runners](https://docs.gitlab.com/ci/pipelines/instance_runner_compute_minutes/)). A runner on Keith's own Windows box is unlimited CI for the Motif gate at $0 marginal. Hosted-runner jobs stop when quota + 1,000-minute grace is gone.

## Auth (all REST/GraphQL/glab hands)

GitLab.com API root: `https://gitlab.com/api/v4/…`. GraphQL: `https://gitlab.com/api/graphql`. MCP: `https://gitlab.com/api/v4/mcp`.

| Method | Header / form | Scope notes | COSMOS use |
|---|---|---|---|
| **Personal / project / group access token** | `PRIVATE-TOKEN: <token>` (recommended) or `Authorization: Bearer <token>` | `read_api` = queries; `api` = writes/mutations. PAT prefix `glpat-`. | Default COSMOS worker credential. Keith mints; never hard-code; store under `live/config/` (git-ignored). |
| **OAuth 2.0** | `Authorization: Bearer` | Same scopes. MCP uses OAuth 2.0 DCR (dynamic client registration) or a pre-registered app with scope `mcp`. | `glab auth login`; GitLab MCP in Cursor / Claude Code. |
| **Pipeline trigger token** | Form `token=` + `ref=` on `POST …/trigger/pipeline` | Impersonates the creating user's project access. Maintainer/Owner creates it. A PAT here returns **404** — that is a documented footgun. | Fire-and-forget CI from COSMOS / webhooks / Cursor push sidecar. |
| **CI job token** | `JOB-TOKEN: $CI_JOB_TOKEN` (or form/`job_token=`) | Lives only while the job runs; fewer endpoints than a PAT. **Cannot authenticate GraphQL.** | Inside a GitLab job talking to packages/registry/downstream pipelines. |
| **Deploy token** | HTTP Basic / Docker login | Registry + repository only. **Not** general API. | `docker pull/push`, generic package download. |
| **Session cookie** | `_gitlab_session` | GraphiQL / web UI. | DOM fallback only. |

**Rate limits (GitLab.com, authenticated user):** 2,000 API req/min; pipeline create **25 / min / project / commit / user**; issue create 200/min; notes 60/min; raw file 300/min; GraphQL complexity 250 authenticated / 200 unauthenticated; GraphQL timeout 30s. `429` = wait. ([GitLab.com settings](https://docs.gitlab.com/user/gitlab_com/))

**glab env:** `GITLAB_TOKEN` (overrides stored creds), `GITLAB_HOST` (default `https://gitlab.com`), `glab auth login`. In CI, `GLAB_ENABLE_CI_AUTOLOGIN=true` uses `CI_JOB_TOKEN` when no PAT is set.

## How COSMOS reaches GitLab (three lanes, one authority)

COSMOS Core remains the sole ledger writer. GitLab is a **worker / return-watcher / publish surface**, never a second authority.

| Lane | Mechanism | When |
|---|---|---|
| **A. Native worker + `glab`** | `glab ci run` / `glab ci status --wait` / `glab mr` / `glab api` inside an attempt-private workspace after Keith's `glab auth login`. | Default. Matches "no bats — in-app / COSMOS action." |
| **B. HTTP through spend-gate** | REST `POST /projects/:id/pipeline`, trigger-token `POST …/trigger/pipeline`, GraphQL `POST /api/graphql`. Poll until terminal status. | Headless, no CLI, or from a cloud agent that only has HTTP. |
| **C. Inbound webhook** | Project hook → COSMOS HTTPS receiver (pipeline/job/push/MR events). `X-Gitlab-Token` secret + `X-Gitlab-Event`. | Return-watcher: stop polling; the forge knocks. |

Cursor Cloud Agent push to a branch is already a **Git-side trigger** of lane A/B (push → branch pipeline). That is free and already connected (DHx).
